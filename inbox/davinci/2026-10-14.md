### 2. Text+ numeric requests must be calibrated on native pixels, then verified through Fusion readback

- **Projects / targets:** `Mason Content Org` caption revisions and completed `Podcast Polina Clips` v2 restyling.
- **Tracking failure:** Fusion `CharacterSpacingClone` aliases the native `CharacterSpacing` multiplier, whose default is 1. Setting a requested typographic value such as `-15` directly would set the multiplier to `-15`, not to an em-style tracking adjustment. The worker exposed a custom Tracking master mapped as `1 + Tracking/1500`, then read both the custom master and native multiplier back.
- **Calibration:** in the 1440x1080 Inter Medium setup, the same glyph run measured 475 px at multiplier 1.0, 460 px at .99, and 429 px at .97. The .97 result was about 9.68% narrower than default; a .91 numeric trial visibly collided letters and was rejected. This proved Text+ spacing is not a proportional width scale.
- **Position and shadow:** caption placement was checked against the rendered glyph baseline, not only Text+ Center Y. Native Black Shadow used shading element 3; `Enabled3` and `SelectElement` had to be set before reading controls. `Tool.SetInput` was treated as a mutation with unreliable/`None` return, followed by `GetInput` readback. A later revision changed only shadow opacity and softness, with same-frame exported-pixel comparison confirming a lighter diffuse shadow while orange fill, center, size, and spacing stayed fixed.
- **Proof:** all native caption-card text/style readbacks passed before render, exported caption-band pixel checks passed after render, and protected prior caption Inputs remained equal to their saved controls.
